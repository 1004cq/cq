## 三、拟定实施路径

本轮建议先从**前端通知能力**入手，补一个统一的通知中心或通知工具模块，将私聊消息、BOT 消息与群消息的到达事件统一接入。该模块至少应支持三类行为：其一，在用户未停留于当前会话时播放轻量提示音；其二，在页面位于后台且用户已授权时触发浏览器通知；其三，为后续静音会话、全局免打扰和通知偏好扩展预留配置接口。这样可以避免把提示音逻辑散落在 `AppContext` 与 `GroupMessageContext` 中，后续维护也更稳定。

完成通知能力后，再补**生产化部署资产**。这里建议直接在仓库根目录新增 `.env.example`、`ecosystem.config.js`、`Dockerfile`、`docker-compose.yml` 与必要的 `.dockerignore`。这些文件应与当前单体架构、Vite 前端构建和 Node.js 服务端启动方式保持一致，并兼容 SQLite 持久化目录映射。若代码里存在默认管理员密码或数据库初始化说明与文档不一致的问题，还应一并核对并修正文档表述，保证部署说明与真实行为一致。

最后进入统一验证阶段，执行依赖安装、类型检查、构建与关键路径验证。如果构建阶段暴露出通知资源路径、Node 运行方式、Prisma 生成或静态资源托管问题，再逐项修复。待验证通过后，再整理交付说明，并根据需要提交代码。
